Cover letter

I’m a full-stack developer who ships end-to-end products with heavy use of AI-assisted coding. My main recent work is YoyakuYo (Bookyo)—a booking marketplace for salons and local services: a Next.js + Tailwind customer site (browse, categories, guest booking, reviews), a LINE mini-app for the same flows on mobile, an owner back-office (calendar, services, bookings, messaging, verification), and an admin area for shops, claims, and operations. The stack is TypeScript, Supabase/Postgres, and a Node API.

I’m comfortable owning features from database migrations through API and UI. I use AI to move faster on boilerplate and exploration, but I rely on types, linting, migrations, and targeted tests so the result stays maintainable. I’m looking for freelance engagements where I can deliver similar full-stack slices with clear communication and predictable quality.

Project built primarily with AI (Node + Tailwind at meaningful scale)

YoyakuYo / Bookyo is the largest project I’ve built with AI assistance. The web layer is Next.js 14 with Tailwind CSS and next-intl across dozens of routes: marketing landing, browse by region/category, shop pages, guest booking, owner dashboard, and admin tools. The backend is a Node service exposing REST-style APIs for shops, bookings, and LINE-related behavior, backed by Supabase (Postgres) with versioned SQL migrations.

One example of a full vertical slice: shop numbers—assigning each owner shop a short numeric ID (1–5000) via Postgres triggers and sequences, backfill migrations, API lookup by shop_number, search on the public site and in LINE, and display on the owner dashboard alongside verification codes. That pattern (schema → API → multiple clients) repeats across the platform.

I work in the same ecosystem as Astro (React, SSR, component-driven UIs); this product is Next.js rather than Astro, but the scale of Tailwind + TypeScript + Node is comparable.

Unit testing in AI-first workflows

I don’t aim for AI to generate a test for every line. I focus tests on high-risk logic: pure functions, API handlers, and filters where bugs hurt users or data (e.g. multilingual shop matching, intent parsing, notification payloads in our Node API).

Coverage: TypeScript strict checking and ESLint run on every meaningful change; that catches a large class of regressions AI introduces. Regressions: when fixing a bug, I add a test that would have failed before, or extend an existing suite. For schema changes, migrations are reviewed like code—rollback path and idempotency matter more than line coverage on UI.

Workflow: after AI-generated changes, I run build/typecheck and manually smoke critical paths (booking flow, shop lookup). Tests plus types are the safety net when refactoring AI-written code.

Subagents, MCP, orchestration

I use multi-step orchestration in the editor: read-only exploration of large repos in separate passes, then implementation in a focused thread with explicit goals. Subagents are useful for “find every usage of X” or mapping a folder structure without polluting the main context.

Where MCP or similar integrations exist (docs, database, browser), I use them to ground answers in real schema and APIs instead of hallucinated field names. The pattern is: narrow task → verify with search or tool output → commit-sized change → verify build.

AI models & editors

Editor: Cursor as the primary IDE. Models: I switch by task—stronger models for architecture, migrations, and debugging; faster models for repetitive edits and renames. I’m model-agnostic and choose based on context length, cost, and whether the task needs deep reasoning.

Quality control & architecture when AI writes most code

Single sources of truth: Postgres migrations for schema; shared types or API contracts so frontend and backend agree. Conventions: App Router layout patterns, consistent naming, i18n keys instead of scattered literals for user-facing copy.

Gates: tsc, lint, and build before considering a task done. Human review on auth, migrations, and anything that touches many files. Scope: I prefer vertical slices (one feature end-to-end) over huge AI-generated dumps that are hard to review.
